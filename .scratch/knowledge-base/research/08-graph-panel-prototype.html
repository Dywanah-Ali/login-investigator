Question 5. What a click does

  • Every node and edge in the drawing is a record the walk returned, so it has a G label.
  • Light the record: clicking an edge highlights its row in the evidence list and its hop line in the answer. Nothing else: no menu, no expand, no drag that sticks.
  • Nothing: the drawing is a picture. Hover shows the full label, that is all.
  • Expansion ("show me this group's other members") is not on the table for phase 1; it would walk the graph outside the playbook.

Drawing rules used here, from research note 08, section 3.2

  • Layered layout, top to bottom, in the order of the playbook steps: the account, then groups, then assets, then peers. Positions are computed from the payload the same way every time, so the same walk is the same picture. No step captions on the rows (author, 25 October 2026): the shapes and the order carry it.
  • Shape says type: circle for a person, rounded box for a group, square box for an asset, diamond for a device, pill for a network, dashed box for a document. No new colour enters the app. The focus node is the one dark element, in line with ticket 07's hierarchy. Restricted assets carry a small red R, the same red as the severity badge.
  • Edge labels are the relation from the table the edge came from: member of, granted, assigned, shared address. Small arrowheads, drawn outside the node.
  • Every label is a plain string. Long labels are clipped and shown in full on hover.

A small walk, drawn the same way

  • B1 is a sales user cleared by a travel notice. The walk is tiny: lthompson, Everyone, three internal assets, no peers. The drawing shows that at a glance, which is the point: a benign alert looks small.
  • Drawn with the defaults: tab in the third column, organisation only, collapsed assets.

Question 7. The Gephi export: a builder's file

  • Not a screen. One core function writes the whole NetworkX graph, or one neighbourhood, to a GEXF file. GEXF carries colour and size; Gephi's GraphML import drops them (research note 08, section 3.5).
  • Script only: uv run python -m core.graph.export --dataset default --out graph.gexf. The file is opened in Gephi Lite in the browser (no install, no server, the file never leaves the machine) or in Gephi Desktop.
  • Download endpoint too: a button in the app that returns the file. Convenient, and it pushes the whole organisation through the API for a builder's task. The research recommends against.

With this option the evidence panel's action row gains "Download graph (GEXF)" next to "Download artifact (JSON)", and the API contract gains a route that returns every table.

What the file holds

<gexf version="1.2">
  <graph defaultedgetype="directed">
    <attributes class="node">
      <attribute id="0" title="type" type="string"/>
      <attribute id="1" title="sensitivity" type="string"/>
    </attributes>
    <nodes>
      <node id="user-0017" label="mgarcia">
        <viz:color r="31" g="95" b="139"/>
        <attvalues><attvalue for="0" value="person"/></attvalues>
      </node>
      <node id="group-it-admins" label="IT Admins"> … </node>
      <node id="asset-dc01" label="domain controller">
        <attvalues><attvalue for="0" value="asset"/>
                   <attvalue for="1" value="restricted"/></attvalues>
      </node>
    </nodes>
    <edges>
      <edge id="mem-0117" source="user-0017" target="group-it-admins" label="member of"/>
      <edge id="grant-0031" source="group-it-admins" target="asset-dc01" label="granted"/>
    </edges>
  </graph>
</gexf>

Node IDs are the ground-truth IDs (ticket 05, decision 5). Colour by type is set on the node's viz attribute before writing. GEXF reserves id, label and pid as attribute names, so our attributes are type and sensitivity.

Evidence that the export works

Unit test: write the pinned dataset, read it back with read_gexf, node and edge counts per type equal the integrity check's counts (ticket 06 comment, 24 October 2026).
Unit test: a node with a reserved attribute name fails loudly before writing.
The author opens the file in Gephi Lite in the browser once and sees the organisation: 50 people, 3 privilege groups plus departments, 10 assets, devices, 4 VPN addresses. Recorded as the author's look, with the date, in the ticket.
Optional: the same for one neighbourhood (S6's radius) to compare with the panel's drawing by eye.

A screenshot is never the evidence (standing rule); the look and the test are.
