Baseline: `a44fb0f9f66794370cd88dfa2c7b18b2b64f3cc1`.
Implementation commit: `7ba32ca`.
Comparison: `git diff a44fb0f...HEAD`.
Two independent review agents ran the Standards and Spec axes through `mp-code-review`.

## Standards

Documented standards met: the checker is plain core Python with no FastAPI import; no new file
joins the type checker's ignore list; no keys or personal data; the script stays thin like
`fetch_attack.py`.

Gaps and judgement calls reported:

- Five gates had no break-the-gate test: unexpected front-matter field, unquoted value,
  unreadable front matter, a document planned twice, an absent-topic kind with no check.
- The real-brief tests call module functions (`World`, `brief_errors`, `mention_errors`,
  `absent_topic_terms`, `contains_term`) rather than `check_corpus`.
- Smells: the owner-team check duplicated with a suppression clause; `planned` used for two
  different things; status values inline while kinds had a constant; `mention_errors` reads
  only `World`; `check_corpus` is long; the leaver matched with a different boundary rule than
  usernames; a missing space; helper order; tests coupled to the scratch brief.

## Spec

Every acceptance criterion's required test is present; the brief's people, groups, systems,
devices, MFA exceptions, travel days, reset timeline, laptop swap time, leaver and planned IDs
agree with the dataset; no exam words, real companies or S4 description were found.

Findings:

1. Systems named in prose are not checked; an invented system passes.
2. Only `first.last` people are checked; the leaver written as "Finn Archer" in a second
   document passed.
3. The no-technique-ID runbook trait is not gated by code.
4. The word-check evidence line was not yet in the ticket (expected at closure).
5. The brief forbids IP addresses but the script allowed table addresses.
6. "Granted to IT Admins" for the VPN gateway and identity provider could lead the writer to
   contradict the 44 ordinary VPN sign-ins.
7. The 29 September meeting said a review was done that happens on 30 September.
8. The new starter guide was dated before MFA and the current password policy.
9. The ATT&CK rule allowed thirteen IDs but only where descriptions allowed them, which they
   barely did.

- Standards: five break-the-gate tests added; owner check folded into one loop over the header
  fields, which also removes a duplicate error for unquoted values; `STATUSES` constant;
  `planned_ids` renamed; helper order and spacing fixed; the leaver now uses `contains_term`.
- Spec 2: the leaver is matched by username and by written name, with a test for each.
- Spec 5: any IP address now fails, matching the brief; the unused networks fixture removed.
- Spec 6 to 9: brief corrected (B-083).
- Spec 4: the evidence line is written into the ticket.

Not taken, with reasons:

  criteria do not ask for the trait. Registered as AUD-055 for the author's T16 read.

  functions it is checked with are its door.
- Long `check_corpus`, `mention_errors` as a method, the test's own derivation of hidden terms
  and its whole-word matcher, and the scratch-brief coupling: judgement calls left as they are.
  The test derives hidden terms independently on purpose, and the brief under test lives where
  the spec puts it.

Evidence after the fixes: 34 corpus tests and 555 backend tests pass; type checker clean;
`git diff --check` clean. No unresolved findings on either axis beyond AUD-055.
